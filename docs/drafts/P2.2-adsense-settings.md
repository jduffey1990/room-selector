# P2.2 — the AdSense settings only the owner can flip

Written 2026-08-03. Everything in the repo half of P2.2 is shipped and
verified. This file is the other half: the account-side settings, why code
cannot do them, and exactly what to click.

## Why this file exists

The P2.2 constraints are hard requirements — vignettes only, no ads in money
or fairness UI, no forced-countdown or non-dismissible formats. Measured
2026-08-03 against Google's current documentation:

- **Auto ads format toggles are AdSense-UI only.** There is no page-level
  parameter for them. `enable_page_level_ads` (the old `overlays: {...}`
  control) is legacy, replaced by account-side Auto ads settings in 2016.
- **"Excluded areas" is also UI-side**, and Google states plainly that it
  "only applies to in-page Auto ads… won't prevent overlay ads such as anchor
  ads." So it is a second layer, never the guarantee.

Neither can be set from this repo, and neither can be trusted as the sole
control. That is why the enforcement in `src/ads.js` is *where the loader
script exists* rather than *what the account is configured to serve*: a route
that never loads `adsbygoogle.js` cannot show an ad in any format, whatever
the account says.

## Already done in the repo — do not redo

| Thing | Where | State |
| --- | --- | --- |
| Ownership verification | `<meta name="google-adsense-account">` in `index.html` | Deployed, live in the served HTML |
| `ads.txt` | `public/ads.txt` → `dist/ads.txt` | Deployed, served as a real file at `/ads.txt` |
| Route gating | `src/ads.js` + `<AdsGate/>` in `src/App.jsx` | Deployed |
| Guarded regions | `data-ad-free` on submission / results / admin roots | Deployed |
| Proof | `verify/ads-placement.mjs` | 39/39, both viewports, dark, zero console errors |

The verification tag is deliberately the **meta tag, not the loader snippet**.
The snippet in `<head>` would put ad code on every route of this SPA,
including `/results/:tripId`. The privacy policy shipped in P2.1 already
promises in writing: *"There are no ads on the pages where you rank beds,
adjust prices, or read your result."* A head snippet would make that sentence
false.

## Owner steps, in order

### 1. Finish verification

AdSense → **Sites** → `roomselector5000.com` is at "Your site needs review".
Both verification signals are already live, so this is just confirming:

- Pick either method — the meta tag or ads.txt; both are in place.
- Tick the "I've finished" checkbox, click **Verify**, then request review.

Sanity check first, from any machine:

```bash
curl -s https://www.roomselector5000.com/ads.txt
curl -s https://www.roomselector5000.com/ | grep google-adsense-account
```

Review is Google's timeline, not ours. Nothing in the repo blocks it.

### 2. Auto ads formats — the hard constraints

AdSense → **Ads** → **By site** → edit `roomselector5000.com`:

| Format | Set to | Why |
| --- | --- | --- |
| Vignette ads | **ON** | The one format the owner chose: it occupies the navigation moment, not the page |
| Banner / in-page ads | **OFF** | In-page markup is exactly what must never land near a dollar figure |
| Multiplex ads | **OFF** | In-page |
| Related search | **OFF** | In-page |
| Anchor ads | **OFF** | Overlay; not chosen, and excluded areas cannot stop it |
| Side rail ads | **OFF** | Overlay |
| Ad intents (links, anchors, chips) | **OFF** | Turns page *text* into ad links — it would rewrite the words explaining what someone pays |

Ad intents deserves the emphasis: it is the one format that edits the copy
itself. On a page that explains a fairness guarantee, that is worse than a
banner.

### 3. Excluded areas — the second layer

Same screen → **Ad settings** → **Excluded areas**. Excluded areas take CSS
selectors, and the guarded roots already carry a stable one:

```
[data-ad-free]
```

This is belt-and-braces only. It covers in-page formats, which step 2 already
turns off, and it does not touch overlays. The route gate in `src/ads.js` is
the real control.

### 4. Re-verify after ads actually serve

Until the site is approved, **no ads serve at all**, so today's clean run is a
baseline rather than a proof. Once approved and Auto ads is on, re-run:

```bash
node seed/seed-demo-trips.js --clean && node seed/seed-demo-trips.js
APPCHECK_DEBUG_TOKEN=<registered debug token> \
PLAYWRIGHT_BROWSERS_PATH=./node_modules/.cache/ms-playwright \
  node verify/e2e-napa-flow.mjs <tripId> <participantCode> <adminCode>
APPCHECK_DEBUG_TOKEN=<registered debug token> \
PLAYWRIGHT_BROWSERS_PATH=./node_modules/.cache/ms-playwright \
  node verify/ads-placement.mjs <tripId> <participantCode> <adminCode>
```

Run the e2e first — `ads-placement.mjs` needs a **finalized** trip or the
results assignment cards never render and the most important assertion in it
quietly checks an empty page.

## What is still not decided

The Better Ads Standards constraint (no forced-countdown, no non-dismissible)
needs no action: AdSense vignettes on the web are dismissible by design, and
the countdown format that violates the standard is an AdMob mobile-app format
with no AdSense web equivalent. Recorded here so nobody goes looking for a
toggle that does not exist.
